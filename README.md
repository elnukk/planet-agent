# planet-agent

## Wiring Convex to the Frontend

The backend schema and Convex function stubs are already written for you in `convex/`. `ConvexProvider` is already wired up in `src/app/layout.tsx` — add `NEXT_PUBLIC_CONVEX_URL` to your `.env` (run `npx convex dev` to get the value). Your job is to implement the Convex functions and replace the existing `localStorage`-based logic with real Convex queries and mutations.

### Step 1 — Implement the Convex function stubs

Open `convex/workflows.ts` and `convex/conversations.ts`. Each file has comments describing every function you need to write. Follow the same pattern as the already-implemented `convex/users.ts`:

- Import `query` / `mutation` from `"./_generated/server"` and `v` from `"convex/values"`.
- Use `ctx.db.get()` for single-row lookups, `ctx.db.query().withIndex()` for indexed lookups, `ctx.db.insert()` for creates, `ctx.db.patch()` for updates, and `ctx.db.delete()` for deletes.

---

### Step 2 — Replace `localStorage` with Convex hooks in the frontend

`src/lib/auth.ts` currently stores users and workflows in `localStorage`. Once your Convex functions are implemented, replace each `localStorage` call with the appropriate Convex hook in the component that needs the data.

**In any React component or page:**

```ts
import { useQuery, useMutation } from "convex/react";
import { api } from "../../convex/_generated/api";

// read data (live, auto-updating)
const workflows = useQuery(api.workflows.getUserWorkflows, { userId });

// write data
const createWorkflow = useMutation(api.workflows.createWorkflow);
await createWorkflow({ userId, intakeJson, notebookCells, sourceCells });
```

**Key replacements to make:**

| Current (localStorage) | Replace with (Convex) | File to update |
|---|---|---|
| `createAccount()` / `signIn()` | `createUser`, `getUserByEmail` | `src/app/page.tsx` |
| `getUserWorkflows()` | `getUserWorkflows` query | `src/app/dashboard/page.tsx` |
| Workflow load on page open | `getWorkflow` query | `src/app/workflow/[id]/page.tsx` |
| Workflow save after generation | `createWorkflow` mutation | wherever the workflow is assembled |
| Workflow edit via chat | `updateWorkflow` mutation | `src/components/workflow/ChatSidebar.tsx` |
| `softDeleteWorkflow()` | `deleteWorkflow` mutation | `src/app/dashboard/page.tsx` |
| Chat history load | `getConversation` query | `src/components/workflow/ChatSidebar.tsx` |
| Sending a chat message | `sendMessage` mutation | `src/components/workflow/ChatSidebar.tsx` |

---

### Tips

- `useQuery` returns `undefined` while loading — handle this with a loading state.
- Mutations return a `Promise` — `await` them and catch errors.
- The `api` object is auto-generated by Convex from your function files. If you add a new function, restart `npx convex dev` to regenerate it.
- You can inspect your database live in the [Convex dashboard](https://dashboard.convex.dev).

## Wiring the Intake Bot to Convex

This section zooms in on the specific task of saving a completed intake form to the Convex database. All the relevant code lives in `src/app/intake/page.tsx`.

### How the intake flow works right now

1. The user steps through the form (use case → time frame → product → region → follow-up questions).
2. On the final summary screen (`StepSummary`), two API calls fire automatically:
   - `POST /api/generate-workflow` — generates a workflow name and preview image.
   - `POST /api/synthesize-intake` — sends the full conversation to Claude and gets back a structured `IntakeJSON` object (region, date range, planet product, inferred intent, constraints, etc.).
3. When the user clicks **"Create Workflow"**, `handleCreate()` runs. Right now it calls `createWorkflow()` from `src/lib/auth.ts`, which saves to `localStorage` and redirects to `/workflow/<id>`. **This is what you need to replace.**

---

### Step 1 — Run `npx convex dev`

This generates the `convex/_generated/` directory, which contains the typed `query`/`mutation` helpers and the `api` object. Nothing else will work without it. Leave the process running — it watches for changes.

---

### Step 2 — Implement `createWorkflow` in `convex/workflows.ts`

Write the mutation that saves a completed intake to the database. It needs to accept every field the schema requires. Here is the full signature:

```ts
import { mutation } from "./_generated/server";
import { v } from "convex/values";

export const createWorkflow = mutation({
  args: {
    userId:              v.id("users"),
    useCase:             v.string(),
    timeFrame:           v.union(v.literal("3mo"), v.literal("6mo"), v.literal("1yr"), v.literal("2yr"), v.literal("5yr"), v.literal("custom")),
    dataFrequency:       v.union(v.literal("daily"), v.literal("weekly"), v.literal("monthly"), v.literal("quarterly")),
    region:              v.any(),
    dateRange:           v.object({ start: v.string(), end: v.string() }),
    temporalResolution:  v.optional(v.union(v.literal("daily"), v.literal("weekly"), v.literal("biweekly"), v.literal("monthly"), v.literal("seasonal"), v.literal("unknown"))),
    planetProduct:       v.string(),
    inferredIntent:      v.optional(v.string()),
    userDescription:     v.optional(v.string()),
    constraints:         v.optional(v.array(v.string())),
    followUpQA:          v.array(v.object({ question: v.string(), answer: v.string() })),
    notebookCells:       v.array(v.object({ cellType: v.union(v.literal("code"), v.literal("markdown"), v.literal("text")), source: v.string() })),
    sourceNotebooks:     v.array(v.object({ filename: v.string(), cellIndex: v.number(), content: v.string() })),
  },
  handler: async (ctx, args) => {
    const now = Date.now();
    return await ctx.db.insert("workflows", {
      ...args,
      createdAt: now,
      updatedAt: now,
    });
  },
});
```

### Step 3 — Get a Convex user ID before saving

`createWorkflow` expects a `userId: v.id("users")` — a real Convex document ID, not the random UUID stored in `localStorage`. You need to look the user up (or create them) in Convex first.

In `StepSummary`, add a second mutation alongside `createWorkflow`:

```ts
import { useMutation } from "convex/react";
import { api } from "../../../convex/_generated/api";

const createWorkflowMutation = useMutation(api.workflows.createWorkflow);
const createUserMutation     = useMutation(api.users.createUser);
```

Then at the top of `handleCreate`, resolve the Convex user ID:

```ts

    name:  localUser.name,
    email: localUser.email,
  });
  // createUser already checks for duplicates and returns the existing id if found
  ...
}
```

### Step 4 — Replace `handleCreate` with the Convex mutation

`handleCreate` currently calls `createWorkflow` from `src/lib/auth.ts`. Replace it with your Convex mutation, passing all the intake data gathered from the form state and `intakeRef.current`:

```ts
const workflowId = await createWorkflowMutation({
  userId:             convexUserId,
  useCase,
  timeFrame:          "custom",           // or derive from startDate/endDate if you want to be precise
  dataFrequency:      frequency.toLowerCase() as "daily" | "weekly" | "monthly" | "quarterly",
  region:             intakeRef.current?.region ?? {},
  dateRange:          { start: startDate, end: endDate },
  temporalResolution: intakeRef.current?.temporal_resolution as "daily" | "weekly" | "biweekly" | "monthly" | "seasonal" | "unknown" | undefined,
  planetProduct,
  inferredIntent:     intakeRef.current?.inferred_intent,
  userDescription:    intakeRef.current?.user_description,
  constraints:        intakeRef.current?.constraints,
  followUpQA:         questions.map((q, i) => ({ question: q, answer: answers[i] ?? "" })),
  notebookCells:      [],     // filled in later when the notebook is assembled
  sourceNotebooks:    [],
});

router.push(`/workflow/${workflowId}`);
```

Remove the old `createWorkflow`, `storeWorkflowImage`, and `storeWorkflowIntake` calls — the data now lives in Convex.
